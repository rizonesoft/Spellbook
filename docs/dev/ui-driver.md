# UI Automation driver

Run `pwsh scripts/drive.ps1 -Scenario shell` from the repository root. It builds Debug through the repository runner, starts one owned app with a new `--data-dir`, checks the title and empty heading through UI Automation, reads the current SQLite schema without write access, captures the rendered window, and requires a clean exit. `-Config Release` selects Release. `-Help` describes the parameters.

The default published image is `docs/captures/shell/main-window-<dpi>dpi.png`; its adjacent JSON receipt records observed physical bounds, dimensions, DPI, actual XAML theme, high-contrast state, image hash, executable/PRI hashes, source HEAD, assertions, and the isolated run directory. Full logs, requests, capture originals, failures, and replacement recovery remain under `build/drive/`. Successful runs remove only their own data directory unless `-Keep` is supplied; failures retain it. Tests never use the user's application data.

Reviewers and automated reruns use a fresh ignored root, for example `pwsh scripts/drive.ps1 -Scenario shell -CaptureRoot build/reviews/my-review/captures`. This exercises identical assertions without changing candidate images. The driver refuses to overwrite published images or receipts with uncommitted changes. Both previous files are preserved under the run's `publication-recovery/` directory before replacement; an ordinary publication failure restores the earlier pair. A restoration failure retains those originals and reports their location. This is recoverable two-file publication, not a power-loss atomic transaction. Retain the entire run directory when investigating publication or capture failures.

`tests/ui/SpellbookUia.psm1` exports eight documented functions. `Start-Spellbook` records the launched process identity, `Get-Element` requires one matching AutomationId within its window, `Invoke-Element` and `Set-ElementValue` require supported writable patterns, `Send-Keys` guards SendInput with owned foreground focus and released user modifiers, `Save-Capture` uses an owned helper with a timeout, `Read-Log` reads only isolated logs, and `Stop-Spellbook` closes only the process it launched. Keyboard injection does not steal focus. If the user changes focus, the test fails; rerun when the desktop is available. Helpers do not change display scale, contrast, or theme.

Every interactive WinUI control has a stable kebab-case `AutomationProperties.AutomationId`. Accessible names come from app vocabulary resources through content, `AutomationProperties.Name`, or `LabeledBy`. An AutomationId selects a control for a test; it is not a spoken label. The shell exposes `main-root` and `empty-heading`, preserving its resource-backed heading.

`tests/ui/dbread.py <database> <query>` returns columns and rows as JSON. It encodes Unicode/URI-special paths, uses SQLite `mode=ro`, authorizes read statements only, bounds rows and execution time, and supports live WAL reads. Writes, attachments, extension loading, and mutating pragmas fail with a nonzero exit code. BLOB values use a `blob_hex` object.

`pwsh scripts/test-ui-driver.ps1` exercises real owned fixture controls, keyboard input, pattern/selector rejections, read-only database behavior, the real shell scenario, and a temporary wrong-title scenario that must fail while preserving previous capture evidence. `scripts/check-all.ps1` and Windows CI run these probes; CI uploads their evidence. `-ScenarioFile` is an explicit test-script override for failure probes and does not modify the normal scenario.

A capture must belong to the launched visible window, have fresh identity and geometry, and contain contrast in the observed text anchor. These checks reject empty/stale/wrong-window evidence; they do not prove pixel-perfect layout or accessibility quality. D00 T03 §9 owns the full display/theme matrix, image inspection, baseline comparison, and candidate-bound visual acceptance. A single successful native-scale driver run is functional evidence, not that visual acceptance gate.

Platform contracts: [UI Automation identifiers](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/use-the-automationid-property), [PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow), [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), and [SQLite URI filenames](https://www.sqlite.org/uri.html).
