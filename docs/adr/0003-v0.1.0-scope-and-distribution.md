# ADR 0003: The v0.1.0 Scope, Distribution, Updates, and Unattended Runs

- **Status:** Accepted
- **Date:** 2026-10-04
- **Deciders:** the operator, in session on 2026-10-04 (four rounds of questions, answers quoted below)

## Context

The operator asked to "do the rest of the features", to ship an Inno Setup installer with "portable install and normal install", to "make this premium", and for the plan to run unattended through `process-plan`. The M1 to M5 plan covered the core of a prompt manager; this record fixes which premium features join it, how Spellbook is distributed and updated, and how an unattended run may act. It supersedes the packaging and network bullets of `AGENTS.md` and the packaging section of ADR 0001.

## Decisions

### Everything ships in v0.1.0

"All in v0.1.0": v0.1.0 is the premium release. The plan runs M1 to M5 and every feature below before the tag; there is no core-only first release.

### The premium feature set

Chosen from sixteen offered:

- **Capture and cast:** capture the selection in any app as a new spell (a second global hotkey); a taskbar Jump List of recent and favourite spells.
- **Library safety and sharing:** a Trash with restore (30 days); automatic rotating database backups with restore from the app; `.spell` files to share a spell and open one by double-click; a find-duplicates tool that merges.
- **Runes and the editor:** rich runes (choice lists, multi-line runes, built-ins such as `{{@clipboard}}` and `{{@date}}`); spell composition (`{{> Spell title}}`); a smart editor (rune and Markdown highlighting, word count, an offline token estimate); tabs.
- **First run and finish:** a starter grimoire and a short tour on first run; spell metadata (target model, source, notes, rating); crash safety (local crash dumps and a recovery notice on the next start, nothing sent).

Offered and not chosen, kept in `todo/backlog.md`: cast-and-paste into the previous app, a command palette, saved searches. "Open in an AI app" was declined ("No, clipboard only").

### One installer, three modes, plus the portable ZIP

The installer is **Inno Setup 7** (7.1.0, released 2026-08-12, the latest). Its first page offers **Install for me** (per-user, no admin, the default), **Install for all users** (elevates), or **Portable** (to any folder or USB stick: no registry, no uninstaller, no shortcuts). The portable ZIP stays for people who never run setup.

A portable copy is marked by a `Spellbook.portable` file beside `Spellbook.exe` and keeps the database, settings, logs, backups, and crash dumps in `Data\` beside the exe. A portable copy never registers file types or starts with Windows.

### Unsigned for v0.1.0; the Store waits for signing

"Unsigned for now": the installer and exe ship unsigned, and code signing stays in the backlog (`B-006`). SmartScreen will warn on early downloads.

### Channels

GitHub Releases, **winget**, **Scoop** (a Rizonesoft bucket, the portable ZIP), and **Chocolatey** for v0.1.0. The **Microsoft Store** requires the EXE and every PE file in it to be Authenticode-signed with a certificate from a CA in the Microsoft Trusted Root Program, so it "waits for signing": a later section gated on the operator setting up signing.

### An update check, on by default

"Update Check, On by default". This ends the "no network calls" rule with one exception: once a day at most, Spellbook asks the GitHub Releases API for the latest release and, when it is newer, offers to open its download page. The request carries no user data (standard HTTP headers only; GitHub sees the IP address). Settings turns it off; the privacy page in `docs/user/` says exactly what is sent. There is no silent self-update, and nothing else in the app touches the network.

### Platforms and startup

Windows 10 (1809 and later, the Windows App SDK floor) and Windows 11; Mica and other Windows 11 visuals fall back gracefully on 10. "Start with Windows" is **opt in**: the installer offers it unticked and Settings can turn it on.

### Install tests run on this PC

"No, test on this PC": the installer is tested unattended by installing into temporary folders on the development machine and on the CI runner (which is elevated, so it covers all-users installs), then uninstalling. A truly clean machine is checked by hand before the release, as an operator step.

### Unattended runs push after each section

"Push after each section": an unattended `process-plan` run pushes `main` after every stamped section so CI checks each step. It never force-pushes, never amends a pushed commit, and never tags: the release tag waits for the operator's approval (`D99 T01 §7`).

## Consequences

- The plan grows by seven TODO files' worth of sections across Phases 0 to 5, plus a Phase 6 for the channels that need accounts or signing.
- The app gains its first network code (the update check) and its first single-instance and command-line forwarding (needed by `.spell` files, the Jump List, and the capture hotkey).
- Every surface section must be provable by an agent: driven runs go through a scripted UI Automation driver, captures are taken at the machine's native scale, and the parts only a person can judge (other display scales, Narrator, a clean machine) move to operator sections in `todo/99-manual/`.
